Ключевые выводы для разработчика AquaBit

  • КРИТИЧЕСКИЙ БАГ ТОПОЛОГИИ в 1/1 городах (тенино): в Труба.csv, Насос.csv и Клапан.csv поля Начало == Конец содержат 'c' + ID самого участка (e702 -> c702,c702) вместо ID начального и конечного узлов.
  • 5 широких динамических файлов R0..R1439 занимают 99.76% всего дискового объёма, тогда как 8 статических таблиц топологии, нагрузок и кривых — всего 0.24%.
  • Таблица Потребление Узел.csv (~25–35% объёма папки города) на 60–85% состоит из нулей транзитных узлов и алгебраически дублирует произведение Потребители Узел.csv × График потребления.csv — её исключение сразу экономит треть объёма без потери информации.
  • Минутная сетка R0..R1439 (1 440 шагов) представляет собой 60-кратную линейную интерполяцию суточного графика с шагом 1 час: переход на часовые срезы H0..H23 + колонки min/max и отказ от Потребление Узел.csv сокращает объём выгрузки на 98.4%, а компактный формат v2 — на 99.5%.

Недостающие высокозначимые признаки для гидравлической интерпретации:
  • Диспетчерское поле 'Название' в статических таблицах (Узел, Труба, Насос, Клапан, Источники)
  • Скорость потока в трубах (velocity_m_s / max_velocity_m_s) — без неё невозможен контроль заиливания и эрозии (>5 м/с) по Принципу 1
  • Свободный напор / давление в узлах (pressure_m) — выгружается только полный пьезометрический напор (Напор Узел), тогда как норматив Требуемое давление задан для свободного напора!
  • Динамический напор и статус насоса (head_m, state) — сейчас выгружается только Поток Насос (Q), чего недостаточно для проверки рабочей точки на кривой Q-H
  • Таблицы резервуаров (Резервуар.csv + уровни РЧВ/ВБ) — необходимы для контроля опорожнения и перелива емкостей
  • Паспорт расчёта manifest.json (шаг расчёта step_seconds, статус сходимости решателя converged, формула потерь напора)
