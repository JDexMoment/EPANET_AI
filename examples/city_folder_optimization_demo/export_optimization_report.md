- **Проанализировано городов / моделей:** `1`

- **Доля избыточных байт (нули + 60× линейная передискретизация + дубль спроса):** **`98.33%`** (`13.15 МБ`)

## 1. Главные закономерности и найденные ошибки выгрузки

1. КРИТИЧЕСКИЙ БАГ ТОПОЛОГИИ в 1/1 городах (тенино): в Труба.csv, Насос.csv и Клапан.csv поля Начало == Конец содержат 'c' + ID самого участка (e702 -> c702,c702) вместо ID начального и конечного узлов.
2. 5 широких динамических файлов R0..R1439 занимают 99.76% всего дискового объёма, тогда как 8 статических таблиц топологии, нагрузок и кривых — всего 0.24%.
3. Таблица Потребление Узел.csv (~25–35% объёма папки города) на 60–85% состоит из нулей транзитных узлов и алгебраически дублирует произведение Потребители Узел.csv × График потребления.csv — её исключение сразу экономит треть объёма без потери информации.
4. Минутная сетка R0..R1439 (1 440 шагов) представляет собой 60-кратную линейную интерполяцию суточного графика с шагом 1 час: переход на часовые срезы H0..H23 + колонки min/max и отказ от Потребление Узел.csv сокращает объём выгрузки на 98.4%, а компактный формат v2 — на 99.5%.

## 3. Детализация по каждому городу

### Город: `тенино` (`13.37 МБ`, 13 файлов, 1440 шагов по 60 с)

- **Строгая валидация Этапа 2:** `fatal`
- **Петли `Начало == Конец` (`SELF_LOOP_LINK`):** `585` шт. *(КРИТИЧЕСКИЙ БАГ СЕРИАЛИЗАЦИИ `'c' + link_id` ПОДТВЕРЖДЁН!)*
- **Осиротевшие ссылки (`ORPHAN_REFERENCE`):** `1170` шт.
- **Неполные Q-H кривые насосов (<3 точек):** `7` шт.
- **Константные графики потребления (`Данные=1`):** `1/7`
- **Аудит `Потребление Узел.csv`:** Транзитных узлов без абонентов: 320/530 (60.38%), полностью нулевых строк в Потребление Узел.csv: 320/530 (60.38%). На проверенных узлах с известными графиками (210 шт.) расхождение с Потребители Узел × График потребления составляет max=0.0050 м³/ч — таблица Потребление Узел.csv на ~100% избыточна и может быть исключена!
- **Недостающие важные гидравлические признаки:**
  - Диспетчерское поле 'Название' в статических таблицах (Узел, Труба, Насос, Клапан, Источники)
  - Скорость потока в трубах (velocity_m_s / max_velocity_m_s) — без неё невозможен контроль заиливания и эрозии (>5 м/с) по Принципу 1
  - Свободный напор / давление в узлах (pressure_m) — выгружается только полный пьезометрический напор (Напор Узел), тогда как норматив Требуемое давление задан для свободного напора!
  - Динамический напор и статус насоса (head_m, state) — сейчас выгружается только Поток Насос (Q), чего недостаточно для проверки рабочей точки на кривой Q-H
  - Таблицы резервуаров (Резервуар.csv + уровни РЧВ/ВБ) — необходимы для контроля опорожнения и перелива емкостей
  - Паспорт расчёта manifest.json (шаг расчёта step_seconds, статус сходимости решателя converged, формула потерь напора)

## 4. Рекомендуемая целевая схема экспорта AquaBit v2 (сокращение с 13 до 9 компактных файлов, уменьшение объёма в 25–50 раз)

1. **`manifest.json`** *(новый, ~1 КБ)*: версия AquaBit, `step_seconds`, `converged`, формула потерь, единицы измерения.
2. **`Узел.csv`** *(обогатить)*: `ID,Название,Высота_m,Требуемое_давление_m,Мин_напор_m,Макс_напор_m,Мин_свободный_напор_m,Макс_свободный_напор_m,Часов_ниже_нормы`.
3. **`Труба.csv`** *(исправить топологию + обогатить)*: `ID,Название,Начало,Конец,Диаметр_mm,Длина_m,Шероховатость_mm,Малые_потери,Мин_поток_m3_h,Макс_поток_m3_h,Макс_скорость_m_s,Смен_направления`.
4. **`Источники.csv` + `Резервуар.csv`**: добавить `Название`, `Узел`, граничный напор/уровни `min/max/init`.
5. **`Насос.csv` + `Клапан.csv`** *(исправить `Начало,Конец`)*: добавить `Название`, номинальный режим/статус, min/max поток и напор.
6. **`Кривая QH.csv`**: `ID,flow_m3_h,head_m` (не менее 3 точек на каждую кривую `u*`).
7. **`Потребители Узел.csv` + `График потребления.csv`**: `node_id,base_demand_m3_h,curve_id` и `curve_id,step_index,multiplier` — **полностью заменяют гигантский `Потребление Узел.csv`!**
8. **`Динамика_24ч` (`Напор Узел`, `Поток Труба`, `Режимы Оборудования`)**: выгружать **24 часовых среза `H0..H23`** вместо 1 440 линейно интерполированных минутных колонок `R0..R1439` (либо Zstd Parquet), исключая полностью нулевые строки резервного оборудования.
