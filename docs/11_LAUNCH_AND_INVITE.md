# Запуск сервиса, проверка и передача ссылки гидравлику

Короткий практический документ: как поднять сайт сбора данных, как убедиться, что он работает,
и как правильно выдать доступ инженеру-гидравлику.
Устройство сервиса и его внутренности — в `docs/10_COLLECTION_SERVICE.md`.

---

## 1. Что где находится

| Что | Адрес | Кому |
|---|---|---|
| Интерфейс разметки | `https://ваш-домен/` | инженерам-гидравликам |
| Персональная ссылка | `https://ваш-домен/?token=ТОКЕН` | одному инженеру (вход без ввода токена) |
| Админка | `https://ваш-домен/admin` | вам |
| Проверка «жив ли» | `https://ваш-домен/health` | вам / мониторингу |
| Автодокументация API | `https://ваш-домен/api/docs` | вам при отладке |

## 2. Локальный запуск (проверка на своём компьютере)

Нужен Python 3.11+. Зависимости ставятся один раз:

```bash
pip install -r requirements.txt
```

### Проще всего: скрипт запуска

Он сам создаёт токены, ставит переменные окружения и печатает готовые ссылки.

**Windows (PowerShell):**

```powershell
cd E:\Code\EPANET_AI
powershell -ExecutionPolicy Bypass -File tools\run_service.ps1
```

**Linux / macOS:**

```bash
cd epanet-ai
bash tools/run_service.sh
```

В выводе будет примерно так:

```
Сервис запускается:
  интерфейс:      http://localhost:8080/
  админка:        http://localhost:8080/admin?token=admin-3f9c…

Гидравлик: Иван Петров (lead)
  персональная ссылка: http://localhost:8080/?token=gidr01-2b71…
```

### Тот же запуск вручную (если хочется без скрипта)

Windows, PowerShell — обратите внимание: переменные ставятся через `$env:`, а не через `export`,
и случайные токены генерирует .NET, потому что `$(openssl …)` в PowerShell не работает:

```powershell
cd E:\Code\EPANET_AI
$env:ADMIN_TOKEN   = "admin-" + -join ((1..8)  | ForEach-Object { "{0:x2}" -f (Get-Random -Maximum 256) })
$env:EXPERT_TOKENS = "gidr01-" + -join ((1..8) | ForEach-Object { "{0:x2}" -f (Get-Random -Maximum 256) }) + ":Иван Петров:lead"
$env:AUTO_EXPORT_HOURS = "6"      # необязательно
python -m uvicorn service.app:app --host 0.0.0.0 --port 8080
```

```powershell
# Windows PowerShell 5.1 не понимает «&&» — команды выполняйте по одной,
# а активировать окружение нужно так:
.venv\Scripts\Activate.ps1        # при запрете политик: Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Linux / macOS, bash:

```bash
cd epanet-ai
export ADMIN_TOKEN="admin-$(openssl rand -hex 8)"
export EXPERT_TOKENS="gidr01-$(openssl rand -hex 8):Иван Петров:lead"
python3 -m uvicorn service.app:app --host 0.0.0.0 --port 8080
```

Дальше откройте **http://localhost:8080/** — при запуске вручную введите токен из консоли
(в PowerShell он будет в переменной `$env:EXPERT_TOKENS`), при запуске скриптом просто
перейдите по напечатанной персональной ссылке.

### Проверка работоспособности

Один и тот же проверяльщик работает на любой ОС (Windows в том числе) — нужен только Python:

```bash
python tools/check_service.py --token <токен гидравлика> --admin <ADMIN_TOKEN>
```

Что он покажет: отвечает ли сервис, доступен ли конвертер `.NET/.epanet`, включён ли расчёт,
открываются ли страницы, пускает ли сервис гидравлика и администратора, сколько моделей и разметок уже собрано.

Если предпочитаете проверять руками: **в PowerShell `curl` — это псевдоним `Invoke-WebRequest`**,
поэтому либо пишите `curl.exe`, либо используйте родные командлеты.

```powershell
# проверка «жив ли» — проще всего так
Invoke-RestMethod http://localhost:8080/health | Format-List

# вход гидравлика (JSON безопаснее собирать так, чем экранировать кавычки в строке)
$body = @{ token = "<токен гидравлика>" } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8080/api/session -Method Post -ContentType "application/json" -Body $body

# админка
Invoke-RestMethod http://localhost:8080/api/admin/overview -Headers @{ "X-Admin-Token" = "<ADMIN_TOKEN>" }

# тем же curl, что и в Linux (curl.exe)
curl.exe -s localhost:8080/health
```

В Linux/macOS то же самое коротко:

```bash
curl -s localhost:8080/health | python3 -m json.tool
curl -s -X POST localhost:8080/api/session -H "Content-Type: application/json" -d '{"token":"<токен>"}'
curl -s localhost:8080/api/admin/overview -H "X-Admin-Token: $ADMIN_TOKEN"
```

Остановка — `Ctrl+C`. Данные (модели, разметка, экспорты) лежат в `service_data/` и переживают перезапуск.

## 3. Запуск на сервере (чтобы работало при выключенном ноутбуке)

Нужен любой VPS (1–2 vCPU, 2 ГБ RAM, 20 ГБ диска) с Ubuntu и доменом, указывающим на его IP.

```bash
# на сервере, один раз
sudo apt update && sudo apt install -y git
git clone <ваш-репозиторий> epanet-ai && cd epanet-ai
bash deploy/install_vps.sh epanet.example.com        # без домена: bash deploy/install_vps.sh
```

Скрипт сам: поставит Docker, откроет порты 22/80/443, скопирует проект в `/opt/epanet-ai`,
сгенерирует `deploy/service.env` (админ-токен и 3 токена инженеров), поднимет сервис и обновление TLS,
включит автозапуск (`restart: always` + systemd), автоэкспорт каждые 6 часов и бэкап в 03:30.
В конце он печатает адрес и все токены — сохраните их.

Проверка снаружи:

```bash
curl -s https://epanet.example.com/health | python3 -m json.tool     # "status": "ok"
```

Обновление после правок кода:

```bash
cd /opt/epanet-ai && git pull && docker compose --env-file deploy/service.env up -d --build
```

## 4. Как правильно отдать ссылку гидравлику

### Вариант А (рекомендуется) — персональная ссылка

Ничего объяснять и ничего диктовать не нужно: инженер открывает ссылку и сразу попадает внутрь
под своим именем. Ссылка берётся в админке: `/admin` → таблица «Эксперты» → колонка
**«Персональная ссылка»** → кнопка «копировать ссылку». Если эксперт ещё не заведён —
создайте его в админке (имя + роль), ссылка появится сразу.

Формат: `https://epanet.example.com/?token=gidr01-3f9c…`

Важно: чтобы ссылки в админке были полными (с доменом), в `deploy/service.env` должен быть указан
`SERVICE_PUBLIC_URL=https://epanet.example.com` — `install_vps.sh` проставляет его сам, если вы указали домен.

### Готовый текст сообщения инженеру

Возьмите в админке кнопку «создать эксперта» — она вернёт `invite` (готовое приглашение) с подставленным
именем и ссылкой. Шаблон, если пишете сами:

> Здравствуйте, Иван Петров!
>
> Мы собираем данные, чтобы обучить ИИ-помощника по EPANET на вашем опыте. Нужно ваше «золотое решение» —
> то, как вы сами разбираете такие модели.
>
> Ссылка (персональная, ничего устанавливать не нужно):
> https://epanet.example.com/?token=gidr01-3f9c…
>
> Порядок: 1) загрузите модель — `.inp`, `.NET` или `.epanet`; 2) посмотрите расчёт, который сделает сервис;
> 3) выберите один из трёх режимов: указать проблему в конкретном элементе, написать эталонный отчёт
> или задать вопрос и дать на него эталонный ответ. Чем конкретнее числа и ссылки на факты (E-001, E-002…),
> тем ценнее пример.
>
> Токен хранится в браузере — повторно вводить не нужно. Если работаете с другого компьютера,
> просто откройте ссылку заново; если вернулись к модели — снова «перетащите» тот же файл,
> сервис узнает его и откроет уже загруженную модель вместе с прошлой разметкой.

### Вариант Б — вручную (адрес + токен)

Отправьте адрес `https://epanet.example.com/` и токен отдельным сообщением; инженер введёт токен
в поле «Вход» на странице. Минус: лишний шаг и токен чаще теряется.

### Правила, которые стоит соблюдать

- **Токен = подпись автора в датасете.** Заводите отдельный токен каждому инженеру: тогда видно, кто
  дал какой эталон (поле `expert_id` в данных). Не выдавайте один токен на двоих.
- **Не отправляйте ссылку/токен в общий чат или рассылку.** Персональная ссылка даёт полный доступ к разметке.
- **Только HTTPS.** По `http://` токен виден в сети; для внешнего доступа всегда домен + TLS (Caddy
  в `deploy/` получает сертификат автоматически).
- **Не давайте инженеру админ-токен и доступ к серверу** — ему нужна только персональная ссылка.
- **Отзыв доступа:** уберите токен из `EXPERT_TOKENS` в `deploy/service.env` и выполните
  `docker compose up -d` — ссылка перестаёт работать, а уже собранные данные остаются у вас.
- **Что доступно инженеру:** только свои загруженные модели и общий список моделей для разметки; чужие
  разметки он не видит. Ограничения на всякий случай: до `MAX_UPLOAD_MB` (по умолчанию 60 МБ) на файл,
  `MAX_UPLOADS_PER_DAY` (40) загрузок в сутки, `MAX_ANNOTATIONS_PER_HOUR` (60) разметок в час.

## 5. Как проверять, что сервис работает и данные идут

Ежедневно достаточно 30 секунд:

```bash
curl -s https://epanet.example.com/health | python3 -m json.tool
```

Смотрите `stats`: `models` (сколько моделей загружено), `annotations` (сколько разметок),
`annotations_unexported` (сколько ещё не попало в архивы), `experts`.

То же самое наглядно — в админке `/admin`: KPI-плитки, таблица экспертов с числом разметок, список моделей,
последние разметки и журнал событий (`login`, `upload`, `annotation`, `export`, `auto_export_failed`).

Если что-то не так:

```bash
docker compose --env-file deploy/service.env ps        # контейнеры должны быть up/healthy
docker compose --env-file deploy/service.env logs -f app | tail -50
```

Автономность проверяется так: закройте ноутбук, а на следующий день посмотрите админку — модели и разметки
инженеров должны появиться, а в списке «Экспорты» — свежие архивы (они создаются каждые `AUTO_EXPORT_HOURS`
часов). Данные лежат в `deploy/data/` на сервере (в Docker — том `/data`).

## 6. Как забрать и превратить в датасет

На своём компьютере, в каталоге проекта:

```bash
# 1) скачать свежий экспорт и сразу прогнать конвейер (валидация → качество → сплиты)
python3 tools/pull_collected.py --url https://epanet.example.com --token <ADMIN_TOKEN> --pipeline

# 2) посмотреть, что получилось
ls data/collected/cases        # кейсы инженеров
ls data/splits_collected       # train/val/test для обучения
python3 tools/check_data_purity.py
```

Если удобнее руками — скачайте архив из админки (кнопка экспорта) и распакуйте так:

```bash
python3 tools/pull_collected.py --zip ~/Downloads/collected_20261006_123132.zip --pipeline
```

Архив содержит кейсы, исходные и очищенные модели, метрики расчёта и **контексты для модели**
(`contexts/<модель>/llm_context_*.json`) — без них примеры были бы без входных данных.

## 7. Если что-то не работает: быстрая диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `export` не распознаётся, `$(…)` не работает | это синтаксис bash, а вы в PowerShell | `$env:ИМЯ = "значение"` либо `powershell -ExecutionPolicy Bypass -File tools\run_service.ps1` |
| `.ps1 не может быть загружен: выполнение сценариев отключено` | политика ExecutionPolicy | запускать так: `powershell -ExecutionPolicy Bypass -File tools\run_service.ps1` |
| `python` открывает Microsoft Store | это заглушка Windows, а не Python | установите Python 3.11+ с python.org (галочка «Add python.exe to PATH») или используйте `py` |
| `curl` выдаёт что-то не то / ругается на `-s` | в PowerShell `curl` — псевдоним `Invoke-WebRequest` | пишите `curl.exe` или используйте `Invoke-RestMethod` (примеры в разделе 2) |
| `&&` не работает в терминале | это Windows PowerShell 5.1 | выполняйте команды по одной либо поставьте PowerShell 7 |
| Инженер открыл ссылку — видит «Ссылка не подошла» | токен изменён/отозван, ссылку обрезал мессенджер | в админке скопируйте ссылку заново; при необходимости введите токен вручную |
| `curl /health` не отвечает | контейнер не поднят, порт закрыт | `docker compose ps`, `ufw status` (нужны 22/80/443), проверьте DNS домена |
| Браузер предупреждает о сертификате | домен ещё не выпущен или не указывает на сервер | подождите пару минут после установки; `docker compose logs caddy` |
| Вход по токену даёт 401 | токен не из `EXPERT_TOKENS`, опечатка, лишний пробел | сравните со `deploy/service.env`, перезапустите сервис после правки |
| Файл не принимается | не `.inp/.NET/.epanet/.zip`, больше лимита, пустой | увеличьте `MAX_UPLOAD_MB` (и `max_size` в `Caddyfile`), проверьте файл локально |
| «Расчёт отключён» в интерфейсе | `RUN_SIMULATION=0` в env | поставьте `1` и перезапустите сервис |
| Разметка не появляется у вас | автоэкспорт ещё не сработал | нажмите экспорт в админке или дождитесь `AUTO_EXPORT_HOURS` |
| Экспорт в админке даёт 500 | ошибка в данных; проверьте логи | `docker compose logs app | tail -50` — там будет причина |
| Инженер говорит «не могу отправить» | сеть/прокси, форма открыта давно | перезагрузите страницу (черновик ответа сохраняется в браузере) |

## 8. Чек-лист «сервис выдан инженерам»

1. `https://домен/health` → `"status": "ok"`.
2. В админке заведены все инженеры, у каждого свой токен и персональная ссылка.
3. Каждому отправлена **его** ссылка + короткая инструкция (шаблон из раздела 4).
4. Вы проверили вход одной из ссылок с телефона/другого браузера — открывается без ошибок.
5. Вы знаете админ-токен, он не отправлен никому, `deploy/service.env` доступен только вам (`chmod 600`).
6. Бэкап и автоэкспорт включены, вы умеете забирать данные (`tools/pull_collected.py --pipeline`).
