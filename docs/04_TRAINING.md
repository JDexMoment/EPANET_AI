# Дообучение модели (LoRA/QLoRA, Qwen3.5-9B)

> **Базовая модель — `Qwen/Qwen3.5-9B`** (решение от 05.10.2026, зафиксировано в
> `configs/model.yaml`): Apache 2.0, ~5–6 ГБ в Q4, работает на клиентском ПК без GPU.
> Резерв — `Qwen3.5-4B` (слабые машины) и `Qwen3.5-35B-A3B` (мощные). Разбор вариантов
> и требования к железу — `docs/09_MODELS_AND_DEPLOYMENT.md`.
> `src/train/qlora_sft.py` берёт модель и гиперпараметры из `configs/model.yaml`.

## 0. Рамка из дорожной карты

- Знания о гидравлике живут в **коде и данных**, а не в весах модели. Модель учим
  стилю ответа, терминологии, структуре, классификации проблем и типовым объяснениям
  (roadmap, п.8).
- Не обучаем арифметике: числа приходят из Analytics Engine.
- Не начинаем с fine-tuning: сначала prompt/context (Этапы 2–3), потом FT (Этап 4).

## 1. Что именно обучаем

| Цель | Данные | Формат ответа |
|---|---|---|
| Стиль и структура объяснения | `data/splits/train.jsonl` | текст (наблюдения → причины → проверки → рекомендации → ограничения) |
| Классификация ситуации | `label` из кейсов (отдельный лёгкий классификатор или instruction «определи категорию») | JSON: category/severity/objects |
| Структурированные ответы | `data/splits/structured.jsonl` | JSON `answer_structured` |
| Отчёты | кейсы `mode=make_report` | markdown с 6 обязательными разделами |

## 2. Базовые линии и порядок работ

1. **Prompt-only** (без обучения): Qwen3.5-9B + наш system prompt + llm_context.
   Замеряем факт-точность и галлюцинации (`data/eval/model_scores.json`).
2. **SFT v1** на 200–500 кейсах (прототип). Обязательное условие входа: валидатор
   принимает ≥ 90 % кейсов, IQA ≥ 0,7 по категории.
3. **SFT v2** на 1 000–5 000+ кейсах, добирая редкие категории (см. отчёт
   `src/eval/metrics_offline.py`: перекосы по категориям и режимам).
4. (Опционально) **DPO/ORPO** на парах «хороший ответ / плохой» — источник: пары
   «инженер ↔ модель» из ревью, где модель ошиблась. Нужны ≥ 300 пар.

## 3. Рецепт QLoRA (стартовый, Qwen3.5-9B)

| Параметр | Значение | Комментарий |
|---|---|---|
| Квантизация | 4-bit NF4, double quant | базовые веса ≈6 ГБ; 1×16 ГБ VRAM хватает |
| LoRA r / alpha | 16–32 / 32–64 | начинать с r=16 |
| target modules | `q,k,v,o,gate,up,down_proj` | полный набор attention+MLP |
| dropout | 0.05 | |
| LR | 1e-4 … 2e-4 | cosine, warmup 3–5 % |
| Эпохи | 2–3 | больше = переобучение на формулировки |
| Batch | 1–2 × grad-accum 8–16 | эффективный batch 16 |
| Seq len | 4096–8192 | контекст ≤ 12 000 символов |
| Precision | bf16 compute | |
| Маскирование лосса | только токены ответа ассистента | контекст не «учим» |
| Температура inference | 0.1–0.3 | инженерный режим, максимум детерминизма |
| Размер QLoRA-адаптера | ~50–200 МБ | удобно версионировать |

Особенности Qwen3.5-9B, которые важно учесть:

* гибридное внимание (Gated DeltaNet + gated attention) → KV-кэш почти не растёт с длиной
  контекста, поэтому даже 8К токенов контекста стоят дёшево по памяти;
* модель мультимодальная «по происхождению», но мы используем **только текстовый путь**:
  vision-энкодер не нужен, изображения не подаём (зрение решается отдельно, см. `docs/08`);
* `enable_thinking=False` в шаблоне — инженерный режим без длинных рассуждений
  (именно так строятся обучающие примеры);
* MTP (multi-token prediction) в обученной модели → можно включить спекулятивное
  декодирование на инференсе для ускорения на 20–40 %;
* параметры сэмплинга карточки (temperature 0.7, presence_penalty 1.5) рассчитаны на чат;
  у нас режим «только факты из контекста» — стартуем с temperature 0.2 (`configs/model.yaml →
  inference`) и фиксируем окончательные значения по `metrics_model`.

Для Qwen3.5-4B (слабые машины): те же параметры, LR 2e-4, seq len 4096; качество ниже
на «Почему это произошло?» и отчётах — сравнивать на одном тест-наборе.

## 4. Гиперпараметры, влияющие на галлюцинации

- Обучение **без** доступа к `truth` и без чисел вне контекста — иначе модель выучит
  «угадывать» причины и числа.
- В датасете обязательно должны быть кейсы «проблемы нет» (`no_problem`) и
  «данных недостаточно» — иначе модель будет находить аварии везде (roadmap п.12,
  hallucination rate).
- Формат ответа с явным разделением «наблюдение / причина / рекомендация» снижает
  выдачу рекомендаций за факты.
- Регулярно прогонять regression-набор (см. `05_EVAL_BENCHMARK.md`) после каждого
  изменения данных или промпта.

## 5. Порядок запуска (заготовки команд)

Подготовка окружения и данных:

```bash
python -m src.dataset.export_instruct            # data/splits/*.jsonl
python -m src.eval.metrics_offline               # проверка объёмов и перекосов
```

Обучение (HF TRL, пример):

```bash
python -m src.train.qlora_sft --print-plan          # проверить план без GPU

python -m src.train.qlora_sft \
  --train data/splits/train.jsonl --val data/splits/val.jsonl \
  --out outputs/qwen3.5-9b-epanet-v1              # всё остальное — из configs/model.yaml
```

> Скрипт `src/train/qlora_sft.py` уже в репозитории и запускается на машине с GPU
> (в песочнице подготовки данных он только проверяет вход и печатает подсказку).
> Он пишет `run.json` с хэшем датасета и гиперпараметрами — без этого бенчмарки «до/после» не сравнить.

Оценка:

```bash
python -m src.eval.metrics_model --pred data/eval/predictions.jsonl \
  --eval-set data/splits/eval_test.jsonl --out data/eval/model_scores.json
```

## 6. Реализация SFT (контракт)

```python
# src/train/qlora_sft.py (сокращённо; полная версия в репозитории)
# 1) читаем data/splits/train.jsonl: {"messages":[system,user,assistant]}
# 2) применяем chat-шаблон Qwen3.5 (enable_thinking=False в инженерном режиме)
# 3) маскируем лосс на токенах system+user (labels=-100)
# 4) QLoRA 4-bit + bf16, cosine LR, 2 эпохи, grad accum
# 5) сохраняем адаптер и версию данных (хэш train.jsonl) в outputs/<run>/run.json
```

Версионирование обязательно: в `run.json` пишем хэш датасета, параметры, метрики
`metrics_model` на тест-наборе и версию system prompt. Без этого бенчмарки «до/после»
не сравнить (roadmap п.12).

## 7. Железо (ориентир)

| Модель | Обучение (QLoRA) | Inference (Q4) | Скорость (локально) |
|---|---|---|---|
| **Qwen3.5-9B** (основная) | 1×16 ГБ VRAM | ~5–6 ГБ | 10–20 ток/с CPU · 30+ ток/с GPU |
| Qwen3.5-4B (слабые ПК) | 1×12 ГБ VRAM | ~3 ГБ | 20–40 ток/с |
| Qwen3.5-35B-A3B (мощные) | 1×24 ГБ VRAM | ~18–20 ГБ | 25+ ток/с с GPU/offload |

Целевые SLA из дорожной карты: p95 ответа ≤ 8 с при контексте ≤ 12 000 символов.
