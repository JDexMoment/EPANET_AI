# ADR-0005: Подключаемый адаптер LLM и выбор компактного студента `Qwen3-4B-Instruct`

- **Статус:** Принято
- **Дата:** 2026-10-30
- **Этап:** Этап 0 / Этап 7 / Этап 9

## Контекст

Целевая среда эксплуатации модуля у инженеров AquaBit включает локальные рабочие станции и закрытые контуры (в том числе CPU / edge-узлы с `llama.cpp` Q5_K_M или локальный `vLLM`), тогда как генерация эталонного корпуса `training.jsonl` (Этап 9) выполняется моделью-учителем (`DeepSeek-V3` / `Qwen2.5-72B`), а тесты CI/CD должны стабильно проходить в офлайн-песочнице без GPU.

## Решение

1. **Единый протокол `LLMBackend` (`src/aquabit_ai/llm/`):**
   - `OpenAICompatibleLLMBackend` — универсальный HTTP-клиент для `vLLM`, `llama.cpp server` и облачного API учителя (`DeepSeek-V3`), возвращающий строго структурированный JSON (`summary`, `critical_issues`, `recommendations`, `limitations`).
   - `DeterministicStubLLMBackend` — детерминированный офлайн-провайдер для интеграционных тестов пайплайна без GPU, использующий те же самые структуры `facts_inline` и проходящий тот же пост-валидатор чисел и трассируемости.
2. **Выбор модели-студента `Qwen3-4B-Instruct-2507` (QLoRA через Unsloth):**
   - Поскольку вся математика и агрегация вынесены в детерминированный Python-слой (ADR-0002), от LLM требуется только качественный русскоязычный инженерный синтез по готовому JSON-контексту и строгое следование JSON-схеме со ссылками `source`.
   - Размер 4B параметров в квантовании `Q5_K_M` (~2.9 ГБ RAM/VRAM) позволяет запускать модель локально на ноутбуке расчётчика с низкой задержкой, сохраняя высокое качество следования инструкциям и русскоязычной терминологии ВКХ после дистилляции на ≥200 примерах.

## Последствия

- Архитектура Этапов 0–6 и пост-валидатора Этапа 7 полностью независима от конкретного способа хостинга модели.
