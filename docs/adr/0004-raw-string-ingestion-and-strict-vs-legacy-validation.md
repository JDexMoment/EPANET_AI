# ADR-0004: Согласование строгой валидации контракта ZIP (Этап 2) с режимом обратной совместимости (Этап 3.1) и диагностический HTML при `fatal`

- **Статус:** Принято
- **Дата:** 2026-10-30
- **Этап:** Этап 1 (Ingestion) / Этап 2 (Validation) / Этап 3.1 (Preprocessing)

## Контекст

В ТЗ зафиксированы два взаимосвязанных требования:
- В **Этапе 2 (Validation)** нечитаемый UTF-8 (`ENCODING_ERROR`) и табуляция вместо запятой (`DELIMITER_MISMATCH`) помечены как `fatal` с подсказкой разработчику AquaBit соблюдать спецификацию §2.
- В **Этапе 3.1 (Preprocessing)** предусмотрена обратная совместимость со старыми выгрузками (например, историческими файлами «Тенино» в `Windows-1251` или с разделителем `\t`), где при обнаружении `\t` выдаётся предупреждение и выполняется чтение с фиксацией в `preprocessing_log.jsonl`.
- Кроме того, критерий приёмки §5.7 требует: при любом `fatal` в валидации конечный инженер должен получить понятный HTML-отчёт с диагностикой, а не Python traceback.

## Решение

1. **Сырой байтовый снимок на Этапе 1:** распаковщик `ingest` сохраняет как сырые байты и детектированные метаданные файла (кодировка, BOM, фактический разделитель строки заголовка, SHA-256), так и строковый `DataFrame` без автотипизации. Если файл повреждён или не читается в UTF-8, `ingest` не выбрасывает неперехваченное исключение наружу, а передаёт дескриптор проблемы на Этап 2.
2. **Двухпрофильная политика валидации (`strict=True` по умолчанию vs `--legacy-compat`):**
   - По умолчанию (`strict=True`) модуль проверяет строгий контракт ZIP v1.0 (§2): не-UTF-8 даёт `ENCODING_ERROR (fatal)`, разделитель `\t`/`;` даёт `DELIMITER_MISMATCH (fatal)` с адресной инструкцией разработчику экспорта AquaBit.
   - При явном включении флага `--legacy-compat` (для миграции и инспекции старых выгрузок AquaBit) перекодируемая `cp1251` и разделитель `\t` понижаются до `warning`, позволяя Этапу 3.1 штатно перекодировать файл и залогировать операцию в `preprocessing_log.jsonl`. Нечитаемые битые байты остаются `fatal` в обоих режимах.
3. **Самодостаточный `report.html` при `status="fatal"`:** если хотя бы одна проверка имеет `severity="fatal"` (включая `MISSING_FILE`, `MANIFEST_INVALID`, `ORPHAN_REFERENCE`, `DUPLICATE_ID`, `DUPLICATE_CURVE_ID`, `SCHEMA_MISMATCH`), пайплайн немедленно останавливается до ИИ-слоя и рендерит автономный `report.html` (inline CSS + встроенные SVG, без внешних CDN) с перечнем ошибок, примерами проблемных строк и рекомендациями по исправлению экспорта.

## Последствия

- Устранён конфликт между строгой приёмкой нового экспортёра AquaBit и возможностью обрабатывать архивные выгрузки.
- Пользователь всегда получает читаемый `report.html` и `validation_report.json` даже на битых архивах.
