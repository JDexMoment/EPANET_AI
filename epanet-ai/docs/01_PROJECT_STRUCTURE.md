# 01. Структура проекта

Один активный трек: **«скриншот AquaBit → ответ»** (локальная VLM на парах
«скриншот + ответ Gemini»). Отменённые треки прошлых постановок вынесены в `archive/`
(см. `archive/README.md`), чтобы не путать структуру.

```
epanet-ai/
├── README.md                     # карта проекта и быстрый старт
├── requirements.txt              # зависимости рабочего конвейера (обучение — на GPU-машине)
│
├── configs/
│   └── vision.yaml               # ЕДИНЫЙ конфиг трека: вопрос по умолчанию, модель Qwen3-VL,
│                                 #   лимиты картинок, гиперпараметры LoRA, сплиты по группам,
│                                 #   пороги метрик, параметры деплоя
│
├── src/
│   ├── common.py                 # пути, json/jsonl/yaml, хеши, rel_to_root, seed
│   ├── vision/
│   │   └── preprocess.py         # препроцессинг картинок: размер под Qwen3-VL, dHash, метаданные
│   ├── model_io/                 # чтение моделей: .inp / .NET (бинарный EPANET 2) / .epanet
│   │   └── vendor/emc/           # парсеры EPANET-Model-Cleaner (MIT)
│   ├── dataset/
│   │   ├── import_screenshots.py     # присланные пары (картинки + ответы) → манифест
│   │   ├── check_screenshot_pairs.py # QA: дубли/почти-дубли (dHash), отказы, числа вне экрана,
│   │   │                             #   группировка для сплитов (+авто-кластеры похожих кадров)
│   │   └── build_vl_dataset.py       # сплиты ПО ГРУППАМ + форматы swift/sharegpt + eval_reference
│   ├── train/
│   │   └── vl_lora.py            # план обучения Qwen3-VL (LoRA/QLoRA) + генерация скриптов
│   │                             #   (ms-swift или transformers+peft)
│   └── eval/
│       └── metrics_vl.py         # метрики ответов: numbers_f1, ids_f1, meaning_f1, grounding,
│                                 #   hallucinated_n, refusal_rate, length_ok_rate + пороги
│
├── data/                         # только реальные данные (см. data/README.md)
│   └── screens/                  # ДАТАСЕТ ЗАКАЗЧИКА
│       ├── raw/                  # сюда кладут присланное как есть (картинки + ответы)
│       ├── images/               # рабочие копии картинок
│       ├── ocr/                  # текст, «видимый» на экране (если приложен)
│       ├── pairs_template.csv    # шаблон таблицы пар
│       └── manifest.jsonl / qa_report.json / {train,val,test}.jsonl — создаются конвейером
│
├── tools/
│   ├── prepare_pairs_worksheet.py # заготовка листа пар: скриншоты → пустые ответы + pairs.csv
│   ├── aquabit_inp.py             # .inp AquaBit: сводка · поиск ID · проверка чисел (Q→V→i) ·
│   │                              #   конвертация в ванильный EPANET (см. docs/13)
│   ├── extract_claims.py          # «гидравлические утверждения» из ответов + сверка с .inp
│   ├── assistant_prototype.py     # прототип приложения: скриншот + модель → карточка, расчёт, график
│   ├── make_demo_screens.py       # синтетический демо-датасет для автотестов (НЕ для обучения)
│   ├── check_data_purity.py       # в датасете нет синтетики и утечек из фикстур (dHash)
│   └── smoke_test.sh              # автотест всего трека на фикстурах (5 шагов)
│
├── tests/fixtures/               # синтетика ТОЛЬКО для автотестов
│   ├── networks/aquabit_demo.inp # фикстура формата AquaBit (статусы, [PRESS], кастом-опции)
│   └── screens_pairs/            # 6 демо-пар «скриншот + ответ» + OCR-тексты
│
├── docs/
│   ├── 01_PROJECT_STRUCTURE.md   # этот файл
│   ├── 09_MODELS_AND_DEPLOYMENT.md  # модель и железо клиента, сборка GGUF
│   ├── 12_SCREENSHOT_FINETUNE.md    # обучение и метрики (главный документ трека)
│   ├── 13_DATA_AUDIT.md             # аудит материалов заказчика (Семей)
│   ├── 14_PIPELINE_AND_INTEGRATION.md  # как всё устроено: пайплайн, роль .inp, интеграция
│   └── 15_AQUABIT_DATA_HOWTO.md        # как собирать данные: пары, экспорты, отчёты
│
└── archive/                      # отменённые треки (не участвуют в работе)
```

## Разделение ответственности

| Роль | Зона работ | Артефакты |
|---|---|---|
| Разработчик AI-модуля | конвейер данных, обучение VLM, метрики, утилиты | `src/`, `tools/`, `configs/vision.yaml`, `docs/12–15` |
| Заказчик (вы) | скриншоты из AquaBit, ответы Gemini, экспорт `.inp` / отчётов | `data/screens/raw/` → рабочая копия датасета вне репозитория |
| Вендор AquaBit (ЭкоИнфраИнжиниринг) | по запросу: выгрузка результатов расчёта (Excel/CSV/`.RPT`) | см. `docs/15`, §3.3 |
| Инженеры заказчика | не размечают датасет (нет ресурса) — только точечные замечания к спорным ответам | `claims.csv` (по желанию) |

## Что куда кладётся (кратко)

1. **Скриншоты + ответы Gemini** → рабочая папка датасета (вне репозитория; в репозиторий
   данные не коммитим) → `import_screenshots` → `check_screenshot_pairs` → `build_vl_dataset`.
2. **`.inp`-экспорты AquaBit** → рядом с датасетом; используются утилитами
   `aquabit_inp.py` / `extract_claims.py` для проверки чисел (в обучение НЕ попадают).
3. **Отчёты в PDF** → извлекаются скриптами (текст/таблицы/картинки) и живут как справочный
   материал; при необходимости размечаются отдельной группой.
